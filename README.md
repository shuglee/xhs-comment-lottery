# 小红书抽奖助手 MVP

一个完全在本地运行的 Chrome Manifest V3 页面悬浮工具。点击扩展图标后，它会固定显示在当前小红书页面右上角，从当前已登录页面读取一级评论，以稳定的 User ID 去重，并使用 Web Crypto API 无放回抽取中奖者。

## 安装

1. 打开 Chrome，访问 `chrome://extensions/`。
2. 打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本文件夹 `xhs-comment-lottery`。
5. 安装后刷新已经打开的小红书帖子页面。
6. 建议在 Chrome 拼图菜单中将扩展固定到工具栏；点击图标后，页面右上角会显示悬浮抽奖面板。

## 使用

1. 在 Chrome 中自行登录小红书并打开目标帖子。
2. 点击扩展图标打开页面悬浮面板，确认显示「当前帖子已识别」。
3. 选择中奖人数，点击「开始抽奖」。
4. 可复制结果，或在剩余有效参与者中重新抽奖。

开启「仅限粉丝（测试）」时，扩展先随机抽取候选人，再要求你将鼠标停在评论区红色高亮的头像上。信息卡显示“回关”或“互相关注”才确认中奖；其他关系会排除该候选人并继续抽取。若信息卡无法识别，抽奖会停止，不会猜测粉丝身份。

## 当前实现

- 只接受可被识别为一级评论的记录。
- 从用户主页链接或页面 JSON 数据读取稳定 User ID；不会用昵称替代 User ID。
- 同一 User ID 只保留一次抽奖机会。
- 默认从有效奖池中排除帖子作者本人；仅使用稳定作者 User ID 判断，不按昵称误排。
- 使用 `crypto.getRandomValues()` 和拒绝采样避免取模偏差。
- 重名检测基于整个有效奖池；中奖昵称冲突时显示 User ID。
- 抽奖状态保存在 `chrome.storage.local`。
- 无服务器、无独立账号体系、无远程数据上传。
- 只在用户点击扩展后使用 `activeTab` 临时访问当前页面；没有常驻小红书域名权限。
- 不直接调用小红书私有接口、不拦截请求、不读取 Cookie、不批量访问用户主页。

## 小红书页面兼容策略

小红书 Web 的类名与内部数据结构会变化，因此当前提取器采用两条路径合并：

1. 读取页面内 `application/json` / `__INITIAL_STATE__` 数据，识别常见 comment、user、parent comment 字段。
2. 从评论节点内的 `/user/profile/{User ID}` 链接获取稳定身份，并通过父评论/回复容器结构排除楼中楼。

抽奖前扩展会以节流方式滚动当前页面的评论容器以触发正常分页加载，连续多轮没有发现新用户后停止，并恢复原滚动位置。页面改版后如无法读取，扩展会明确报错，不会退化为按昵称去重。

## 使用与账号风险

本扩展按“用户主动、单帖子、读取当前页面可见数据”的原则实现，刻意避免私有接口调用、后台批量任务、高频用户主页访问、登录绕过和风控绕过。这比服务器爬虫或批量接口采集风险低很多，但第三方平台规则和风控会变化，任何工具都无法保证绝不触发限制。建议只为自己管理的抽奖低频使用，不要连续批量处理帖子，也不要将评论或用户数据导出作其他用途。

## 粉丝限定

「仅限粉丝」仍处于测试阶段。扩展不会预先验证整个评论池，而是抽出一个候选人后，提示用户亲自悬停其头像，读取信息卡中的关系状态；仅把“回关”和“互相关注”视为粉丝。非粉丝被排除后继续随机抽取。验证严格串行，已识别的关系在本地缓存 24 小时；任一候选人无法可靠读取时会停止抽奖，不会猜测其身份。该功能尚不能保证兼容小红书 Web 的所有页面状态。

## 已知限制

- 安装或更新扩展后，需要刷新已打开的帖子页面。
- 小红书页面结构属于第三方实现，未来改版可能需要更新字段映射与结构选择器。
- 只能读取当前登录账号在网页端实际可见、可加载的评论。
